슬라이드 1: 프로젝트 아키텍처 개요

현 상태: 멀티 모듈 모놀리스

이 프로젝트는 유지보수성과 관심사 분리를 위해 단일 모듈에서 Maven 멀티 모듈 구조로 리팩토링되었습니다.

모듈 구조

모듈 역할 의존성
core 도메인 계층. 공통 DTO, 유틸리티. 없음
api 서비스 계층. 비즈니스 로직 및 API 엔드포인트. core에 의존
spa 애플리케이션 계층. 웹 진입점, UI, 설정. api에 의존
핵심: 코드는 논리적으로 분리되어 있지만, spa 모듈에 의해 관리되는 단일 실행 가능한 JAR로 빌드됩니다.

슬라이드 2: 실행 메커니즘 및 흐름

동작 방식

  • 빌드 단계: 부모 POM이 빌드를 관리합니다. core와 api는 JAR 라이브러리로 컴파일됩니다.
  • 패키징 단계: spa 모듈이 이 라이브러리들을 최종 JAR 내부의 BOOT-INF/lib에 번들링합니다.
  • 런타임: JVM은 spa의 메인 클래스(AiaApplication)를 실행하며, api와 spa 패키지의 컴포넌트를 스캔합니다.

데이터 흐름


사용자 (브라우저/HTTP) 
  --> SPA 모듈 (Controller/View) 
    --> API 모듈 (Service) 
      --> Core 모듈 (DTO)

슬라이드 3: 개발자 명령어 (CLI)

1. 빌드 (필수)

모듈 간 의존성이 있으므로, 먼저 로컬 Maven 저장소에 설치해야 합니다.

./mvnw clean install

2. 애플리케이션 실행 (개발 모드)

spa 모듈에서 Spring Boot 애플리케이션을 실행합니다.

# -pl spa : Project List 'spa' (특정 모듈 대상)
./mvnw spring-boot:run -pl spa

3. 프로덕션 실행

# 8080 포트로 실행 (기본값)
java -jar spa/target/aia-spa-0.0.1-SNAPSHOT.jar

# 사용자 지정 포트로 실행
java -jar -Dserver.port=9090 spa/target/aia-spa-0.0.1-SNAPSHOT.jar

슬라이드 4: 신규 기능: Mock API 및 대시보드

구현된 기능

  1. Mock API 엔드포인트
    • URL: GET /api/mocks
    • 로직: 하드코딩된 MockData 객체 목록을 반환합니다.
  2. 웹 대시보드
    • URL: GET /aia/dashboard
    • 뷰: Thymeleaf 템플릿 (dashboard-view.html).

개발자 실행 항목

  • spa / api에 spring-boot-starter-web 및 thymeleaf 의존성이 필요한지 확인하세요.
  • core나 api 코드를 변경한 후에는 항상 mvn install을 실행하여 spa에 반영하세요.
